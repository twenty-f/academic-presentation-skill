# 学术演示文稿

## 启动与首次试用

- 用户已经给出具体任务时，直接进入对应工作流程。用户明确要求试用或重新看引导时，直接打开下方虚构试跑示例。
- 用户只要求启动或打开 Skill 时，读取与本 `SKILL.md` 同目录的 `.onboarding.local.json`，只使用 JSON 中的布尔字段 `onboarding_seen`。值为 `true` 时，直接请用户提供材料和本次任务。文件缺失或字段未设为 `true` 时，问一次「引导式试用」还是「直接开始」，等用户选择。
- 收到其中一项的明确选择后，将 `{"onboarding_seen":true}` 写入该文件。选择「引导式试用」就按[虚构试跑](examples/fictional-pilot.md)引导。选择「直接开始」就接着处理用户的任务，或请用户提供论文、笔记或 PPT 和要完成的事。后续聊天读取同一份本地记录。写入失败时继续执行已选模式，并说明该选择只在当前聊天里有效。

## 开始任务

先确定用户要方案、审稿还是制作。识别听众、讲述目标、时间、语言和目标放映软件。对无关紧要的缺项采用合理默认并说明。用户还在逐条提供修改意见时，先归集，按其约定的开始条件再改稿。

## 新稿

- **只有论文**时，读清研究问题、方法机制、实验可比性和作者的适用边界。先核对本次要讲的关键结果，再决定叙事顺序和页数。
- **论文加既有笔记**时，保留有出处的研究判断和用户确认，针对展示需要补读原文。区分作者结论、团队复现、讲者解释和未验证推测。
- 按[叙事与证据](references/narrative-and-evidence.md)组织。先用代表性例子建立问题，让方法图、实验对照和结论沿同一条问题链推进。[逐页计划表](templates/slide-plan.md)可用于记录页意图、证据和备注。

## 改稿

先确认底稿和要改的对象。移动页面时，用版本、页标题或证据对象、目标邻页一起定位。保留已认可的叙事、素材和正确的编辑对象。批量修订另存版本，复核受影响的页、邻页和讲稿衔接。[版本修订](references/revision-and-delivery.md)

## 制作与验收

- 优先使用宿主已有的演示文稿工具。制作任务交付实际可打开的可编辑 PPTX，重要文字、表格和自制图形优先保留为可编辑对象。原论文图适合以原图引用时，保留图注、出处和解释所需的标记。将讲者备注写入实际演示稿。
- 逐击演示按[动画与放映核验](references/reveal-and-playback.md)设计。每次点击安排一个讲解变化。用[动画资源指南](references/animation-library.md)按关键词找组件，或选一份完整分镜改成自己的例子。动画能力不足时用静态分步或相邻页呈现。
- 从实际交付文件回读关键主张、页序、备注及对象。分别说明结构检查、静态渲染、模拟点击和目标软件实播的覆盖范围。只在目标软件实测过时报告相应实播结果。宿主缺少 PPTX 制作能力时，提供能完成的逐页计划和讲稿，说明缺少的工具。

[虚构试跑](examples/fictional-pilot.md)用于快速验证流程与输出边界。
