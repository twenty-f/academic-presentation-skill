# 版本修订与交付

1. 指定起点。记录用户认可或指定的文件版本，用标题、表号、图或备注定位受影响页面。移动时同时核对将要放在哪一页之后或之前。若页码和内容冲突并导致不同改法，先明确目标。
2. 归集反馈。把同一要求去重，区分保留、修改和待用户定夺。用户要求等反馈收齐时，先记录，待其给出开始信号。保留原稿，交付另存的版本。
3. 安全改动。尽量在原对象上改，不用替换整页来修改一句话。保持文本、表格、备注及必要媒体的可编辑性；针对移动对象或重排页面回查转场、分节、页码引用和相关备注。动画依赖对象顺序时，核对完整播放序列。
4. 给出证据。回读实际交付文件，检查关键主张、页序、备注和引用。新稿看全稿，局部修订重点看改动与邻页。验证存在的 PPTX 和 PDF 分别可打开，若缺少查看能力就说明哪一步未测。交付时给出实际路径和版本，写清仍影响使用的缺口。

交付用途决定文件集合。正式制作通常包含 PPTX 和其内部备注；PDF、静态预览和单独 QA 记录按用户需要提供。方案阶段可以用逐页计划加讲稿供确认。
